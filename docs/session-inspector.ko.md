# 세션과 비용을 이해하는 방법

[English](session-inspector.md) · [한국어 데모 열기](https://niceysam.github.io/tracefrugal/?lang=ko)

`tracefrugal`을 실행하고 기간을 고른 뒤 세션 행을 누르세요.
그래프는 최근 응답을 보여주고, 상세 분석은 **선택한 기간에 남아 있는 전체 응답**을
사용합니다. 최근 그래프에 표시되지 않는 응답도 통계에 포함됩니다.
선택 기간 밖의 기록까지 포함한 세션 전체 수명과는 다를 수 있습니다.

## 1. 어떤 대화인지 구분하기

세션 번호·프로젝트·모델·최근 활동 시각을 확인하세요. 프로젝트 이름이 같은
두 행이라도 서로 다른 대화일 수 있습니다.

**내가 알아볼 세션 이름**에 “결제 API 문제 분석”처럼 이름을 붙이세요.
이름은 현재 브라우저의 현재 주소에만 저장됩니다. 브라우저나 포트가 바뀌거나
사이트 데이터를 지우면 보이지 않을 수 있습니다. 비우고 저장하면 초기화됩니다.
**프로젝트 이름 숨기기**는 세션 화면의 프로젝트 이름과 별명을 숨깁니다.
도구·저장소 이름까지 모두 익명화하는 기능은 아닙니다.

| 지표 | 뜻 |
|---|---|
| 입력 P50 | 입력량을 작은 순서로 정렬했을 때 중앙에 있는 값 |
| 입력 P95 | 응답의 95%가 이 값 이하의 입력을 사용 |
| 최대 입력 | 선택 기간에 가장 큰 요청의 입력 |
| 응답 수 | 도구 반복 호출·기록된 서브에이전트를 포함. 사용자 질문 횟수와 다름 |
| 누적 처리 토큰 | 같은 컨텍스트의 반복 처리를 포함. 컨텍스트 창 크기와 다름 |

백분위는 가까운 순위(nearest rank) 방식이며 캐시 읽기·쓰기를 포함합니다.

## 2. 질문은 짧은데 입력이 큰 이유

입력은 사용자가 새로 쓴 질문만 뜻하지 않습니다. **모델 요청마다 받아보는
지침·이전 대화·도구 정의·도구 결과** 등이 함께 들어갑니다.

| 화면의 내용 | 토큰으로는 |
|---|---|
| 모델이 작성한 답변·코드·패치·도구 호출 인자 | 생성할 때 출력. 다음 요청에 유지되면 그때는 입력 |
| 브라우저 `Result`, 파일 내용, 명령 실행 결과 | 도구가 반환해 다음 모델 요청에 넣은 입력 |
| 터미널 diff·진행 로그·줄인 미리보기 | 화면 글자 수만으로 청구 토큰을 판단할 수 없음 |

예를 들어 **요청당 입력 10만 토큰 × 모델 요청 10회 = 누적 입력 100만 토큰**입니다.
질문 한 번에도 도구 사용 중 모델을 여러 번 요청할 수 있습니다.
실제로는 컨텍스트가 커지거나 잘리거나 압축됩니다.

캐시가 적중하면 적용 단가는 낮아지지만 입력 토큰에는 계속 포함됩니다.
캐시 재사용이 항상 보장되지는 않습니다. 대시보드의
**“질문은 짧았는데 왜 입력 토큰이 이렇게 많을까요?”**를 펼치고 슬라이더를 움직여 보세요.

근거: 2026년 9월 12일 확인한 OpenAI 공식
[도구 호출 흐름](https://developers.openai.com/api/docs/guides/function-calling)과
[프롬프트 캐시](https://developers.openai.com/api/docs/guides/prompt-caching).
기능 지원과 단가는 모델·제공업체에 따라 다릅니다.

## 3. 비용 계산식 확인하기

**항목별 금액 = 토큰 수 ÷ 1,000,000 × 백만 토큰당 단가**

새 입력·캐시 읽기·5분 캐시 쓰기·1시간 캐시 쓰기·출력을 각각 계산해 더합니다.
모든 가격 산정 가능 응답의 금액을 합친 것이 세션 추정 비용입니다.

상세 화면은 모델과 실제 적용 단가가 같은 응답끼리 묶습니다.
지원되는 지역 가산율은 표시된 단가에 이미 들어 있습니다.
구독료·협상 할인·크레딧·세금·제공업체별 계약 조건은 반영하지 않습니다.
**공개 표준 단가 추정치이지 실제 청구서가 아닙니다.**
가격표 확인 날짜도 표시하며 자동 갱신을 보장하지 않습니다.

알 수 없는 모델·캐시 유지 시간·지원하지 않는 요금 구간은 사유와 함께
**금액 미산정**으로 남깁니다. Codex 로컬 사용량도 금액 미산정입니다.
이를 0달러로 해석하면 안 됩니다. 일부만 계산 가능하면 ‘산정된 부분 합계’로 표시합니다.

## 4. 비교하고 개선하기

**다른 세션과 나란히 비교**에서 응답 수·평균/P95 입력·캐시 읽기·출력·비용을 보세요.
요청이 더 많거나 모델·작업 난도가 다르면 합계도 달라집니다.
다른 세션의 비교만으로 실제 절감이나 동일한 품질을 입증할 수는 없습니다.

큰 도구 결과는 조회 필드·줄·페이지부터 줄이세요. 아직 유효한 결과를 재사용하고
독립적인 읽기를 묶으세요. 선택적으로 [MCP 결과 축소 프록시](mcp-pack.md)를 시험할 수 있습니다.
도구 정의는 지원되는 환경의 도구 검색·지연 로딩과 컨텍스트 분석 화면에서 확인하세요.
현재 로그만으로 질문·지침·도구 정의·이력의 정확한 토큰 비중을 분해할 수는 없습니다.

범위를 정한 24시간 시험과 답변·추론 만족도를 함께 기록하세요.
더 확실히 판단하려면 비슷한 작업을 반복하고 정확성을 검증하세요.
입력만 작아졌다고 성공은 아닙니다.

**집계 데이터 JSON 저장**은 세션 번호·시각·모델·토큰·분포·가격표를 내보냅니다.
프로젝트 이름·별명·원본 타임라인·프롬프트·도구 본문은 제외합니다.
별도의 API 보고서 가져오기 화면에 넣는 형식은 아닙니다.
모델명과 사용 시각도 민감할 수 있으니 공유 전에 확인하세요.

## 언어 선택

로컬 사용량 화면과 API 시험 화면 모두 위쪽에서 **한국어 / English**를 선택합니다.
주소의 `?lang=ko` 또는 `?lang=en`이 최우선이며, 그다음 저장한 언어, 브라우저 언어 순입니다.
코드·모델명·도구명·직접 붙인 이름은 원문을 유지합니다.
번역 API를 호출하지 않고 앱에 포함된 문구를 사용합니다.
