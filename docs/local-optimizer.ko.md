# 내 Claude Code 환경 최적화

[English](local-optimizer.md) · [실제 CLI 검증 기록](optimizer-validation.md)

TraceFrugal은 내 프로젝트의 **실제 설정을 변경**하고 사용 결과를 비교하며,
필요하면 원본 설정으로 돌려놓는 로컬 프로그램입니다.
브라우저는 내 컴퓨터에서 실행되는 프로그램의 조작 화면입니다.

## 사용 순서

1. [실행 파일](https://github.com/niceysam/tracefrugal/releases/latest)을 받고
   압축을 푼 뒤 계속 사용할 위치에 두세요. 평소 Claude로 작업하는 프로젝트에서:

   ```sh
   tracefrugal optimize --project .
   ```

   PATH에 없다면 실행 파일의 전체 경로를 쓰세요. Windows는 `tracefrugal.exe`입니다.
2. 화면의 **CLI 경로·버전·프로젝트·공식 문서·변경 내용**을 확인하고
   **최적화 적용 · 원본 백업**을 누르세요. 만족도를 비워 두면 미측정으로 남습니다.
3. 같은 프로젝트에서 평소 쓰던 Claude CLI로 **새 세션**을 시작하세요.
   화면에서 적용값 확인 → 시간별 입력·캐시·출력·호출 수·비용 비교 →
   답변·추론 만족도 평가 순서로 확인합니다.
   좋으면 계속 쓰고, 아니면 **기존 설정으로 원복**을 누르세요.
   **새 실험으로 다시 적용**하면 이전 이력을 보존한 채 다시 비교합니다.

프로그램 자체는 모델을 호출하지 않습니다. 평소 Claude 작업의 요금은 그대로
발생합니다. 화면을 닫아도 설정은 유지됩니다. 같은 명령으로 다시 열면 보관된
로그에서 사용량을 읽습니다.

## 여러 Claude가 설치되어 있다면

현재 자동 적용은 실제 검증한 **Claude Code 2.1.268**에 한정합니다.
다른 버전은 조회만 가능하며 CLI를 자동 업그레이드하지 않습니다.
여러 운영체제의 단위 테스트 통과가 각 운영체제의 실제 Claude 검증을 뜻하지는 않습니다.

```sh
tracefrugal optimize --project /작업/프로젝트 \
  --claude-bin /실제로/사용하는/claude \
  --claude-dir /실제/claude/설정폴더
```

기본 CLI는 PATH에서 찾고, 설정 폴더는 `CLAUDE_CONFIG_DIR` 또는 `~/.claude`입니다.
qc 같은 런처가 다른 바이너리·설정 폴더를 선택한다면 명시해야 합니다.
화면에 기록이 없다고 사용량이 0인 것은 아닙니다.
`tracefrugal doctor`는 같은 옵션으로 설정을 바꾸지 않고 진단 결과를 출력합니다.

## 정확히 무엇을 바꾸나요?

해당 프로젝트의 `.claude/settings.local.json`에
`env.MAX_MCP_OUTPUT_TOKENS = "6000"`을 설정하고,
실제 적용값 확인용 `SessionStart` 훅을 추가합니다.
기존 모델·추론 강도·권한·MCP 연결·로그인 정보는 유지합니다.
기존 파일 전체를 먼저 백업하고 변경 이력과 문서 확인 기록을 남깁니다.

Claude가 기준보다 큰 MCP 텍스트 결과를 로컬 파일로 보관하고,
에이전트가 필요한 내용을 읽도록 하는 방식입니다.
자체 크기 제한을 지정한 도구는 예외이며 모든 입력을 6,000토큰으로 제한하지는 않습니다.

**주의할 실제 동작:** 저장된 파일은 일반 텍스트이거나 텍스트를 감싼 JSON일 수 있습니다.
JSON 파일 200번째 줄과 결과 본문의 200번째 줄은 다를 수 있습니다. 두 형식을 고려해야 합니다.
잘못 읽으면 추가 호출·재작업·정보 누락이 생깁니다.
그래서 토큰만 줄었다고 성공으로 판정하지 않습니다.

검증한 최신 CLI는 MCP 도구 정의의 지연 로딩이 이미 기본이므로,
무조건 `auto:5`로 바꾸는 추천을 하지 않습니다.

## 공식 문서 확인과 실제 적용 확인은 다릅니다

진단할 때 실행 파일 버전과 Anthropic의 MCP·설정·훅·변경 이력 문서를 확인합니다.
고정된 공식 URL만 조회하며 프로젝트 내용은 전송하지 않습니다.
인터넷의 글을 실행 코드로 바꾸지 않고 미리 검토한 규칙을 적용합니다.

공식 문서는 계속 갱신되는 문서이므로 특정 버전의 고정 명세는 아닙니다.
문서의 키워드와 해시만으로 호환성을 입증하지 않습니다.
버전 제한과 실제 CLI 시험을 함께 사용합니다.

저장 후에는 새 Claude 프로세스가 기록한 **실제 설정값**을 확인합니다.
그 세션·버전·프로젝트가 일치하는 사용 기록만 적용 후 집계에 넣습니다.
설정 적용 확인은 절감이나 품질 보장의 증거와는 다릅니다.
다른 저장소·버전·연결되지 않은 하위 에이전트 기록은 제외됩니다.

## 비교와 원복

같은 프로젝트·저장소의 직전 24시간과 적용 후 최대 24시간을 비교합니다.
작업 난이도·모델·캐시·관측 시간이 다르면 숫자가 달라질 수 있습니다.
응답당 입력이 줄어도 호출 수가 늘었다면 전체 비용은 증가할 수 있습니다.
만족도와 재작업 여부도 확인하세요. 실제 요금 청구액이 아닌 토큰 기준 추정 금액입니다.

24시간이 지나도 설정은 유지됩니다. 시간별 그래프는 로컬 화면에서 확인하며
유료 평가·이메일 보고·추론 품질 자동 채점은 실행하지 않습니다.
원복 후에는 새 세션을 시작하세요. 이전 컨텍스트·도구 실행·과거 비용은 되돌리지 못합니다.

원복은 원래 파일의 바이트와 권한을 복원하며, 새로 만든 파일이면 제거합니다.
중간에 직접 편집한 설정은 덮어쓰지 않습니다. 이 경우
`<state>/<실험번호>/before.json`과 현재 파일을 비교해 수동으로 합치세요.
백업에는 기존 비공개 설정이 포함될 수 있으므로 공개 저장소에 올리지 마세요.

상태 저장 위치는 실행 시 표시하며 `--state /비공개/경로`로 선택할 수 있습니다.
확인 훅을 사용하는 동안 TraceFrugal 실행 파일의 경로를 유지하세요.
비정상 종료로 `.lock`이 남으면 실행 중인 프로세스가 없는지와 이력을 확인한 뒤
잠금 디렉터리를 제거하고 원복으로 복구하세요.

Codex의 사용량 조회는 기존 대시보드에서 계속 지원합니다.
이번 설정 최적화는 Claude Code 전용입니다.
